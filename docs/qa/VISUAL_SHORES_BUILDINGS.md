# Берега, покрытия и постройки

Дата: 15 ноября 2026. Ветка: `codex/visual-shores-buildings`.
База: `7de13c6f5fcc6e9d5d29eb2c402bada8f515b566`, актуальный `codex/audit-and-stabilization` на начало работы. Результат подготовлен для отдельного PR в эту ветку; автоматическое слияние не выполняется.

## Реализация

Рабочее приложение остаётся Node.js + браузерный Canvas. Новых библиотек, ассетов и сетевых зависимостей нет. Рабочие изменения ограничены `remote/world-art.js`.

### Вода и берега

- Тонкие линии течения и неровности кромки вычисляются в координатах мира с периодом четыре клетки. Они продолжаются на соседнем тайле, включая отрицательные координаты и границы чанков.
- На воде разделены влажный ил, мелководье и глубокий центр. На естественной суше добавлена узкая влажная кромка. Соседняя неизвестная/отфильтрованная клетка не трактуется как сухой берег.
- Сопряжённые прямые края используют закругление радиусом 0.42 клетки: срезаются только углы. Центр водной клетки остаётся водой, включая одноклеточную реку. Эти декоративные срезы не образуют сухой проход поперёк воды.
- Четыре поворота углов, диагональные контакты и смешанные материалы берега проходят автоматические проверки. Вычислительные поля геометрии и фазы повторно используются.

Клеточная форма мира остаётся заметной на крупном масштабе. Это уменьшение ступенчатости, а не замена воды непрерывными сплайнами.

### Покрытия

- Лес и лесная подстилка используют собственную приглушённую основу вместо основы травы.
- Трава, земля, подстилка и грязь смешиваются по общему полю четырёх соседних центров клеток с небольшим пространственным смещением границы. Благодаря этому кромка мягче и не повторяет один рисунок на каждом тайле.
- Смешивание происходит до травинок, камешков и крон: оно не перекрашивает детали деревьев в цвет земли.
- Существующие соединения дорог, скругления поворотов и заполнение внутренних углов широких перекрёстков сохранены. Каменные и деревянные полы сохраняют чёткий край.

Длинные прямоугольные контуры, заданные самим покрытием, не превращаются в новый контур генератора. Кромка детализируется только визуально.

### Постройки

- Для каждого существующего типа (`house`, `tavern`, `barn`) сохранены три воспроизводимых варианта по координатам. JSON-поле варианта не требуется; одинаковый объект у мастера и на ТВ получает одинаковый рисунок. При переносе координатный вариант может измениться, как и в базовой версии.
- Добавлены соломенные связки, сланцевые и черепичные ряды, вальмовые скаты одного из вариантов, сегментированный конёк и карнизы.
- Добавлены узкий деревянный/штукатурный фасад, ставни, связи амбара, слуховые окна некоторых домов и кладка дымоходов. Таверна сохраняет вывеску.
- Все элементы остаются внутри существующего холста крыши с отступом 0.3 клетки. Внешняя тень по-прежнему направлена вправо-вниз независимо от поворота.

Модель мира, размеры объектов, генераторы, API, движение, туман, синхронизация и редактор не изменены. `remote/world-decor.js` не понадобилось менять.

## Автоматическая проверка

Node.js 24.22.1. Чистая база: **135/135**. Итоговый полный набор: **142/142**, без пропусков.

```bash
npm ci
npm test
node --check remote/world-art.js
node --check scripts/visual-shores-qa.cjs
node --check scripts/fixtures/visual-shores-scene.cjs
node --test test/world-art.test.cjs test/world-visual-bounds.test.cjs
git diff --check
```

Новые проверки покрывают непрерывность на -32/0/32, центр одноклеточной реки, неизвестных соседей, закруглённый угол, сочетания материалов/диагоналей, стабильность трёх вариантов всех типов во всех четырёх поворотах и отсутствие изменения исходных данных. Два последовательных полных кадра фиксированной сцены не создают новые тайлы во втором кадре.

Прежний `world-visual-bounds.test.cjs` продолжает проверять все типы, повороты, варианты и скрытые объекты: команды рисования укладываются в существующую визуальную оболочку. Прежние серверные сценарии прохода, обзора, секрета, публикации и сохранений проходят в полном наборе.

## Настоящий браузер

Chrome 156/Linux, viewport 1363×936, DPR 1. Тестовые данные изолированы. Обычный запуск сервера в командной среде оказался недоступен браузерам (`ERR_CONNECTION_REFUSED`). Стенд успешно запущен в сетевой среде облачного браузера из тех же исходников; код приложения ради этого не изменялся.

В обычном интерфейсе мастера выбран черновик «Графика · Река и поселение», осмотрены берег, покрытия и повороты четырёх домов. Публикация открыта на `/tv`. Скрытый сундук виден мастеру и отсутствует на общем экране. Включённый туман без открытий скрывает всю сцену. Ручное открытие участка показывает только небольшой островок с домом; остальные постройки остаются скрыты. После отключения тумана показ восстанавливается.

Стенд browser-qa — одноразовый мастерский прокси; эта ручная проверка подтверждает изображение и UI, а не отдельную проверку авторизации. Разделение ролей проверяет полный набор HTTP-тестов обычного сервера.

Проверены масштабы 15, 24, 42 и 64 пикселя на клетку. Сравнительные кадры сняты отдельной QA-страницей, которая загружает настоящие `WorldMap`, `WorldDecor`, `WorldArt`, `WorldView` из проекта. ## Цена отрисовки

Сравнение на одной геометрии: 2109 тайлов и 55 объектов, камера x=0/y=0/scale=24, Canvas 1363×826. Один синхронный render по видимому прямоугольнику вызывает настоящие paintTile/paintProp и чтение одного пикселя. Начальное построение отдельно измеряется до первого кадра WorldView. Кнопка замера делает 25 повторных кадров, первые пять отбрасываются, из оставшихся 20 вычисляются медиана и p95. Медиана — среднее двух центральных выборок, p95 — 19-я из 20. Сохранены все исходные значения; сводные медианы вычислены из них.

| Версия / повтор | Первое построение, мс | Медиана повторного кадра, мс | p95, мс |
| --- | ---: | ---: | ---: |
| База 1 | 226.2 | 16.0 | 17.3 |
| База 2 | 253.3 | 17.65 | 20.1 |
| Изменения 1 | 300.6 | 19.4 | 41.1 |
| Изменения 2 | 272.5 | 19.1 | 21.8 |

[Исходные выборки](measurements/visual-shores-buildings/). Новая детализация стоит дополнительного времени; ускорение и 60 FPS не заявляются. В первом новом прогоне был выброс 49.5 мс, он не исключён. Это локальный синхронный render, не замер частоты показа кадров, сети, WS, полной сессии или GPU-профиль. Windows, физические телефоны/ТВ и большой нагрузочный мир здесь не измерялись.

При разработке выявлено постоянное вытеснение тайлов при ключе, содержащем фазу даже для внутренней травы. Фаза теперь включается только у реальных переходов/берегов/воды; у воды убран неиспользуемый случайный вариант. Атлас ограничен 1024 тайлами (до 16 MiB RGBA-пикселей без накладных расходов Canvas), 16 полями фазы (~896 KiB) и 32 полями геометрии (512 KiB). Кеш крыш/крон и прочая память браузера в эти цифры не входят. Это не измеренный предел общего RAM. Прежний лимит атласа был 384 тайла; рост памяти — явный компромисс.

## Воспроизведение

В полной рабочей копии с доступным базовым коммитом:

```bash
npm ci
node scripts/browser-qa.cjs
```

Во втором терминале в той же сетевой среде запустить:

```bash
VISUAL_QA_DATA_DIR=/tmp/vtt-browser-qa-ABC node scripts/visual-shores-qa.cjs
```

Заменить путь точным временным DATA_DIR из вывода первого процесса. Принимается только существующая одноразовая папка `vtt-browser-qa-*` прямо в системном tmp с реестром кампаний. Черновик создаётся только при отсутствии; повторный запуск не перезаписывает ручную проверку. Без переменной стенд сравнения работает без записи данных.

Открыть `http://127.0.0.1:3101/?version=before`, переключать версию, кадр и масштаб. Для замеров использовать отдельные свежие загрузки x=0/y=0/scale=24. Базовый WorldArt берётся через `git show` зафиксированного SHA, остальные модули общие. Если история усечена, сначала получить базовый коммит. Стенд слушает только loopback, не публиковать его в сеть. Завершение — Ctrl+C в обоих терминалах.

## Интеграция и ограничения

1. Рассмотреть отдельный PR в `codex/audit-and-stabilization`. Не вливать его автоматически и не заменять основную ветку архивом.
2. При новых изменениях основной ветки проверить конфликт только визуального кода и тестов. Модель/visualBounds не расширять: текущий рисунок уже помещается в прежние границы.
3. После объединения выполнить полный npm test, открыть тестовую сцену у мастера и на ТВ, проверить туман. Основному агенту обновить центральные план и прогресс.
4. Визуальная серия целиком и качество Canvas of Kings не объявляются завершёнными. Остаются клеточность крупных берегов, периодичность полей, детализация дорог/окружения и цена холодного построения на более разнообразных сценах. Новые пределы мира и повышение производительности не входят в этот PR.
