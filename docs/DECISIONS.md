# Технические решения

| ID | Статус | Решение и основание |
| --- | --- | --- |
| D001 | Принято для текущего этапа | Развивать существующий сервер Node.js и Canvas-модули. Уже имеются кампании, два типа карт, редакторы и LAN-синхронизация. Сохраняем совместимые маршруты при добавлении личных проекций. |
| D002 | Принято | Список миров читает обычные файлы черновиков с именем вида `ID.json`. Резервные копии, каталоги и опубликованные `ID-live.json` не участвуют в списке. Повреждённый настоящий черновик требует отдельного сценария восстановления. |
| D003 | Принято как требование | Персональный обзор, исследование и раскрытие секрета — разные состояния. Публикация на ТВ и обмен открытием между героями — разные действия мастера. |
| D004 | К проектированию | SQLite предусмотрена ТЗ 3.0. До выбора драйвера и миграции нужен контракт операций хранилища, оценка упаковки Windows, проверка импорта на копии и восстановление исходных JSON и ассетов. |
| D005 | Реализовано в C1/D2 | Мастер выдаёт приглашение одному герою текущей кампании. Сервер хранит хеш токена. Новая выдача и отзыв закрывают прежние назначенные соединения. |
| D006 | К проверке | Tauri 2 — кандидат из ТЗ. Решение после прототипа управления процессом Node.js, открытия второго окна и проверки упаковки на Windows. |
| D007 | Принято | ТВ объединяет обзор всех героев активного этажа. За пределами обзора сервер выдаёт последнюю виденную местность и публичные объекты. Для старых масок исходная память берётся из публикации, действовавшей до её замены. |
| D008 | Принято | Раскрытие на ТВ относится к конкретной версии скрытого объекта по типу, координатам и повороту. Снимок сохраняется в памяти группы. Изменённый скрытый объект требует нового раскрытия. Личные передачи относятся к D4. |
| D009 | Принято | Версия ТВ складывается из поколения активной карты, ревизии публикации и счётчика исследования. Каждый компонент сохраняется с данными, изменения которых он описывает. После пропуска события ТВ читает статус и запрашивает полный снимок видимого участка. |
| D010 | Принято | Личное открытие сохраняется как снимок по ID героя, карты и объекта. Права просмотра проверяются при чтении по приглашению. Общий экран получает раскрытие отдельной командой мастера. |
| D011 | Принято | Рецепты генераторов хранятся в черновике карты. Тип и версия задают контракт параметров и алгоритма. Числовой seed фиксируется при сохранении, чтобы запуск с теми же параметрами мог повторить результат. |
| D012 | Принято в F4 | Снимок исходного покрытия и ручные исключения сохраняются в рецепте. Регенерация сохраняет ID участка и защищает изменения пользователя. Старые рецепты без снимка требуют нового участка при изменении параметров. |
| D013 | Реализовано и проверено в браузере в F5a | Именованный шаблон хранит только настройки и seed генератора в отдельном файле кампании. Геометрия, исходное покрытие и ручные исключения принадлежат участку. Загрузка шаблона начинает новый рецепт. Добавление проверяет ревизию списка и сохраняет прежний файл при ошибке. |
