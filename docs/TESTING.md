# Проверки

## Запуск

В полной рабочей копии с Node.js 24:

```sh
npm ci
npm test
```

Тесты используют `node:test`. `characters.test.cjs` проверяет конструктор героев, `layout.test.cjs` — размещение панелей, `world-model.test.cjs` — координаты и границы чанков, `sync.test.cjs` — реальный сервер, HTTP и WebSocket, границы кампаний, права мастера, редактор мира и перезапуск. Интеграционный тест занимает порт 3098, запускает поддельный сервер Ollama и использует временный `DATA_DIR`. Он копирует и создаёт изображения в `public/assets/maps`, поэтому его следует запускать в отдельной рабочей копии. Перед запуском проверьте, что порт свободен.

## GitHub Actions

Workflow [CI](../.github/workflows/ci.yml) запускается для PR в `main` и при записи в `main`. На чистом Linux-раннере с Node.js 24 он получает полную рабочую копию с оригинальными ресурсами, ставит зависимости через `npm ci` из lockfile и выполняет `npm test`. Секреты для тестов не нужны. Результат задания Tests (Node.js 24) виден во вкладке Checks в PR.

## Резервная копия и восстановление

1. Остановите сервер. Определите фактический каталог данных: `DATA_DIR`, если задан, иначе `data` рядом с `server.js`.
2. Скопируйте целиком каталог данных и `public/assets` в отдельный каталог резервной копии. Для Docker копируйте фактические данные из смонтированных каталогов или из остановленного контейнера, если ассеты хранятся в нём. Если менялись файлы в `seeds`, сохраните их отдельно. Запишите версию приложения и расположение каталогов.
3. Для проверки подготовьте отдельную установку той же версии с зависимостями. Скопируйте резервные данные в новый каталог и укажите его как `DATA_DIR`. Восстановите ассеты в `public/assets` проверочной установки. Сохраните исходную установку и резервную копию до завершения проверки.
4. Запустите проверочную установку с другим портом и войдите как мастер. Откройте кампанию, персонажа и заметку, проверьте растровую сцену и её редактируемый черновик, затем активный мир и его состояние на телевизоре. При расхождении остановите проверочный экземпляр и проверьте версию, пути и полноту копии.

Тест `node --test test/backup.test.cjs` автоматически создаёт кампанию в одной временной установке, останавливает её, восстанавливает оба каталога во второй и проверяет через HTTP реестр, героя, заметку, сцену, черновик, байты PNG, черновик мира, его публикацию, раскрытый туман и жетон. Он входит в `npm test`. Процедура проверена для локального Node.js на Linux. Ручное восстановление в Docker и Windows в A3 не проверялось.

## Импорт старых карт

`node --test test/world-import.test.cjs` проверяет импорт через командную строку, сохранение байтов оригиналов, отказ при конфликте, повтор после сбоя записи и чтение копии для отката. `sync.test.cjs` дополнительно проверяет чтение импортированной карты по HTTP после запуска сервера. Порядок импорта описан в [схеме мира](WORLD_SCHEMA.md#перенос-и-откат-b4).

## Память карты и текущий обзор

`node --test test/sync.test.cjs` проверяет объединение обзора двух героев, переход известной клетки в память после закрытия двери или ухода группы, изменение и удаление тайлов вне обзора, перемещение объекта, старую маску, восстановление после перезапуска, ручное раскрытие и обновление при новом наблюдении. Проверяется разделение по этажам и отсутствие скрытых объектов в публичном ответе.

Для проверки отрисовки откройте ТВ с включённым туманом. Сделайте шаг героем, затем перенесите его за пределы обзора. Телевизор должен затемнить прежний участок, сохранив виденные тайлы. Измените тайл на этом участке и опубликуйте карту. Правка появится после возвращения героя или ручного раскрытия.

## Раскрытие секрета

Интеграционный тест проверяет скрытый объект до и после отдельной команды мастера, доступ гостя, телефона и ТВ, проверку ревизии, раскрытие одной клетки, соседний секрет, переключение карты, отключённый туман и перезапуск. При переносе раскрытого объекта прежний снимок сохраняется в памяти, а новое положение требует отдельной команды.

Для ручной проверки отметьте объект как скрытый в редакторе. Опубликуйте карту и откройте `/tv`. В управлении опубликованной картой выберите скрытый объект и нажмите «Раскрыть на ТВ». Откройте на ТВ соответствующий участок. Выбранный объект и его клетка должны появиться.

## Синхронизация ТВ

`test/world-table-sync.test.cjs` запускает клиентский скрипт ТВ с управляемыми таймерами и ответами сети. Проверяются пропущенное сообщение WebSocket, сбой загрузки чанков, запоздавшие ответы после обновления или переключения карты и сохранение затемнения при гонке запросов. `test/sync.test.cjs` проверяет совпадение версии в WebSocket и HTTP, повторное подключение к серверу, переключение карты, сохранение версии после перезапуска и неизменность публичной версии при личном шаге без тумана.

Для проверки в браузере откройте опубликованную карту на ТВ и прервите WebSocket, сохранив доступ к HTTP. Откройте дверь или раскройте секрет с компьютера мастера. ТВ должен получить актуальное состояние при очередной проверке видимой вкладки. После возобновления WebSocket следующая правка должна появиться сразу.

## Личные открытия

`test/sync.test.cjs` проверяет передачу разным героям, разделение с ТВ, права чтения и записи, текущую кампанию, устаревшую публикацию, повтор, перезапуск и перевыпуск приглашения. `test/sheet-discoveries.test.cjs` проверяет отрисовку журнала, получение свежего снимка и отбрасывание запоздавшего ответа после отзыва доступа.

Для ручной проверки откройте опубликованную карту, ТВ и две карточки по приглашениям разных героев. В управлении картой выберите скрытый объект и героя и нажмите «Передать герою». Запись должна появиться в разделе «Путь → Личные открытия» выбранного героя. Затем нажмите «Раскрыть на ТВ» для того же объекта и проверьте общий экран.

## Рецепты генераторов

`node --test test/world-generators.test.cjs` проверяет границы координат, seed, ширину, версии, уникальность ID и эталонный поток чисел. `test/sync.test.cjs` проверяет отказ при неверной версии, сохранение рецепта через API, правку чанков, импорт старого формата, перезапуск и выдачу опубликованного снимка без рецептов.

## Инструмент Path

`test/world-generators.test.cjs` проверяет связность дороги по четырём соседним клеткам, ширину реки, обрезку у границы мира, влияние seed и предел размера. `test/world-path-editor.test.cjs` запускает редактор с имитацией браузера и проверяет предпросмотр, применение, отмену, повтор, сохранение и загрузку рецепта.

Для ручной проверки откройте «Большая карта мира», выберите **Path · Дорога или река** и отметьте несколько опорных точек. Выберите покрытие и ширину, задайте seed и нажмите «Предпросмотр». Примените линию к черновику, проверьте «Отменить» и «Повторить» и сохраните карту. Откройте её заново, выберите сохранённый рецепт и проверьте совпадение предпросмотра.

## Forest Plot

`test/world-generators.test.cjs` проверяет вогнутый контур, защиту воды, дорог и существующих объектов, повторяемость seed, повторное применение и лимиты. `test/world-path-editor.test.cjs` проверяет предпросмотр, сохранение, отмену и повтор вместе с тайлами, объектами и рецептом. `test/sync.test.cjs` проверяет сохранение леса через API и чтение после перезапуска. Пробный участок отрисован игровым Canvas-кодом в локальном графическом рантайме.

Для ручной проверки откройте большую карту с дорогой или рекой. Выберите «Forest Plot · Лес», укажите вершины по периметру, настройте плотность и нажмите «Предпросмотр». Сравните рощи и просветы при разных seed. После применения проверьте отмену и заново откройте сохранённый рецепт.

## Отрисовка поселения V1

`test/world-art.test.cjs` проверяет переход от берега к глубокой воде, запись пикселей в координатах изображения, закругление поворотов и заполнение внутренних углов широкой дороги. Для визуальной проверки собрана деревня с травой, рощами, камнем, грунтом, рекой, мостом, жилыми домами, таверной и амбаром. Рендеры до и после получены игровым Canvas-кодом на одной геометрии. Проверены разные повороты построек и читаемость материалов при масштабе 42 пикселя на клетку.

## Регенерация F4

`npm test` на Node.js 24.22.1: 41 тест. Новый `test/world-regeneration.test.cjs` проверяет восстановление покрытия на старом участке и границах чанков, чистоту предпросмотра, стирание и покраску, перенос/скрытие/удаление растений, сохранение ручного дома, повтор после JSON-перезагрузки, пересечения рецептов, совместимость со старыми рецептами, отказ при неверном снимке или превышении лимита и согласованную отмену/повтор.

Сценарий `test/world-path-editor.test.cjs` проверяет реальный код редактора в имитации DOM: ID сохраняется при изменении параметров, ручные правки переживают сохранение и повторное открытие, Undo/Redo возвращает карту и метаданные, замена контура удаляет прежний участок уже в предпросмотре. `test/sync.test.cjs` сохраняет снимок F4 через HTTP, проверяет отказ при неизвестной версии снимка, сохранность метаданных при PATCH и перезапуске и их исключение из публикации.

Для ручной проверки в браузере:

1. Создать новый участок Path или Forest Plot, применить и сохранить.
2. Покрасить и стереть несколько его клеток. У леса удалить одно дерево, другое перенести или скрыть; поставить дом.
3. Сохранить, открыть карту заново и выбрать прежний рецепт.
4. Изменить параметры, проверить предпросмотр и применить регенерацию. Проверить сохранение ручных правок и прежнего ID.
5. Нажать «Изменить точки», задать другой контур или линию. Прежний автоматический участок должен исчезнуть в предпросмотре, ручные правки — остаться.
6. Проверить «Отменить» и «Повторить», сохранить и перезапустить сервер. Повторить генерацию с теми же параметрами: дубликатов и новой записи сохранения быть не должно.
7. Открыть рецепт, созданный до F4: без изменения параметров карта сохраняется, при изменении появляется предложение начать новый участок.
