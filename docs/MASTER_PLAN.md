## Автоматическое продолжение

По команде «Продолжай» прочитать актуальные `docs/MASTER_PLAN.md`, `docs/DEVELOPMENT_PROGRESS.md` и последние коммиты, выбрать следующую невыполненную задачу, реализовать её, проверить тестами и исправить ошибки. Обновить оба документа, сохранить результат в Git и предоставить краткий отчёт со следующим шагом.

Не просить повторять инструкции или выбирать очередную задачу. В новом чате восстанавливать контекст из документации репозитория. Останавливаться при необходимости решения пользователя, опасных изменениях или завершении текущего поручения.

Если запись в GitHub недоступна, сохранить локальный коммит и передать архив с патчем, изменёнными файлами и инструкцией для другого чата. Указать базовый коммит и результаты проверок. До следующей задачи сверять, применён ли предыдущий пакет; локальный результат не выдавать за опубликованный в GitHub.

## Текущий этап

Этапы A и B завершены. Новые карты используют чанковое хранилище. Для старых карт доступен проверенный автономный импорт с сохранением оригиналов. D1 завершена. Реестр доступа и критерии приватности находятся в ACCESS_CONTROL.md. C1a завершена. C1b завершена для личной карточки /player. Приглашения выдаются через /dm/access.html, их отзыв закрывает назначенные WS. D2a завершена. D2b1 завершена. D2b2 закрывает каталоги сцен и ресурсов и выделяет выдачу опубликованных файлов для общего экрана. C2 сохраняет отдельную позицию каждого героя и ограничивает чтение мастером и назначенным игроком. C3 добавляет шаги героя с телефона и перенос мастером с проверкой версии позиции. Общий туман на ТВ автоматически объединяет клетки, пройденные всеми героями, и ручные открытия мастера. C4 проверяет проходимость и связывает отдельные карты-сцены одного мира. E1 добавляет видимые клетки в общий туман после подтверждённого шага. E2 добавляет открываемые двери и отдельные маски исследования этажей. E3 сохраняет последнее увиденное состояние местности и объектов. Телевизор различает текущий обзор группы и память карты. E4 добавляет отдельное раскрытие скрытого объекта на ТВ. Этап E проверен на серверных сценариях общей карты. D3 добавляет версию общей проекции, восстановление после пропуска события и защиту от запоздавших ответов. D4 добавляет личный журнал переданных открытий с проверкой приглашения. Этап D завершён для общего экрана и карточки героя. F1 фиксирует формат рецептов Path и воспроизводимый поток случайных чисел. Рецепты сохраняются в черновике вместе с его ревизией. F2 добавляет Path для дорог и рек с предпросмотром, загрузкой рецепта и отменой применения. F3 добавляет Forest Plot с процедурными рощами и новой отрисовкой леса. V1 задаёт общий визуальный язык и обновляет отрисовку поселения и открытой местности. F4 интегрирована из проверенного пакета: Path и Forest Plot перестраиваются в рамках прежнего ID, восстанавливают исходное покрытие и сохраняют ручные правки. Метаданные генерации и ручных правок входят в одну операцию Undo/Redo с картой и сохраняются в черновике. Старые рецепты без снимка исходного покрытия читаются, но изменение их параметров требует нового участка. База пакета совпала с текущей веткой. Полный набор из 41 теста повторно прошёл после установки зависимостей через npm ci. В F5a реализованы именованные шаблоны настроек Path и Forest Plot в текущей кампании; новый участок получает отдельный ID и собственный снимок. Автоматические проверки проходят. F5a остаётся на приёмке: требуется браузерный сценарий F4 и шаблонов; к Room пока не переходим.

## Визуальный стиль карт

### Технические границы очереди

- Текущая реализация использует Node.js, браузерный Canvas, JSON и клеточные координаты. Упаковка настольного приложения и выбор оболочки относятся к H. Переход на другой движок потребует отдельного решения.
- На карте действует предел 150 000 тайлов и 3 000 объектов. Тайлы хранятся чанками, но редактор по-прежнему получает полный черновик и отправляет полный PUT. Запрос ограничен 8 MiB, а снимки F4 увеличивают размер сохранения. Эти пределы нужно измерить до генерации крупных районов.
- У старых рецептов F1–F3 отсутствует исходное покрытие. Для изменения параметров используется новый участок. Достоверное восстановление прежнего грунта требует снимка F4.
- История отмены содержит до 50 операций текущего открытия. Сохраняются состояние генератора и ручные исключения. Восстановление стека отмены между сеансами потребует отдельной задачи.
- Участки с разными рецептами сохраняют владение клетками. Смешивание перекрывающихся генераторов нужно определить до District Plot.
- Для V2–V4 ещё требуется выполнить перечисленные графические серии. Общий ориентир Canvas of Kings и уже обновлённое поселение V1 сохраняются.

## Порядок интеграции

Первый игровой срез включает двух героев в одной сцене, стену, дверь, скрытую локацию и три вида экрана. Сначала проверяются серверные проекции и права, затем они подключаются к интерфейсам. Текущие растровые сцены и общий мир продолжают обслуживаться существующими маршрутами, пока новый сценарий проходит проверки.

Приёмка первой версии повторяет сценарий ТЗ с тремя героями и заранее подготовленным миром. Герои идут вместе и проходят соседние клетки разными маршрутами. Общий экран показывает объединённую исследованную местность. Мастер отдельно открывает секрет, редактирует карту во время сессии, затем участники переподключаются и сервер перезапускается. Расширенные генераторы локаций, эффекты и выпуск Windows следуют своим этапам.
