# B5b3g — ограниченное повторное использование состояния исследования

14 ноября 2026. База — `96bd5d502847f5e19fb61ca3b3dcdf79ff23f1d2`. Улучшен read-only mapState в character-positions.js. Мутирующие операции, HMAC, роли, формат JSON и лимиты карт сохранены. Пользовательские кампании не использовались.

## Реализация

Одна запись кеша на фабрику registerCharacterPositions. Ключ — абсолютный путь кампании плюс dev/ino/size/mtimeNs/ctimeNs из statSync с bigint. При неизменной идентичности mapState повторно использует разобранное состояние. Смена кампании/версии вытесняет прежнюю запись до чтения; перед собственным writeState кеш явно очищается, включая неуспешную запись.

Допуск — обычный файл с входным JSON до 8 MiB: проверены размер stat и фактический Buffer.byteLength строки. Это ограничение допуска документа, не лимит карт или оценка JS heap. После разбора метаданные проверяются повторно. Если файл изменился или повторная проверка не удалась, возвращается свежее некешируемое readState; повторное изменение при таком чтении имеет прежнюю файловую семантику. Ошибка чтения/разбора не возвращает старый снимок. Отсутствующий, слишком большой или недоступный для stat файл использует прежний путь без кеша.

Допущенное дерево замораживается целиком итеративным обходом. Read-only результат не позволяет испортить общий кеш через вложенные memory/explored/revealedSecrets. openDoors строится новым Set; visible каждый раз вычисляется по текущей геометрии, ростеру героев и состоянию дверей. Роли, итоговый HTTP-ответ и вычисленный обзор не кешируются. Все мутирующие операции продолжают получать новый независимый JSON через прежний readState. Первое чтение/инвалидация по-прежнему требуют полного разбора и дополнительно замораживания; этот срез улучшает повторные неизменённые чтения.

## Методика

До изменения рабочего модуля выполнены [контроль с туманом](B5B3G_CONTROL_FOG.json) и [контроль без тумана](B5B3G_CONTROL_CLEAR.json). После проверки 104 тестов тем же неизменённым стендом последовательно выполнены [кеш A](B5B3G_CACHED_FOG_A.json), [кеш B](B5B3G_CACHED_FOG_B.json) и [кеш без тумана](B5B3G_CACHED_CLEAR.json). Во всех измеряемых sourceSha256 отличается только character-positions.js. applicationRef=null; точные исходники сохранены хешами.

125 районов, 3 000 объектов, 150 000 тайлов, 599 terrain-чанков. Память: 150 002 записи клеток/2 997 объектов; JSON состояния — 4 022 228 байт. Две дополнительные исторические записи не повышают лимит тайлов карты. Один наблюдающий герой, старые снимки, секреты и отрицательный выступ кроны. Пять запросов регионов, один исключённый прогрев каждого, пять измеренных выборок. Итого пять прогонов/125 измеренных HTTP-ответов. Настоящий публичный loopback HTTP без cookie мастера, отдельные процессы и временные данные.

Среда: Node.js 24.22.1, Linux x64, AMD EPYC 9V74. Файловый кеш прогрет, GC сервера не принудительный. Холодный старт/первое замораживание не входят в таблицу повторных запросов. Клиентское wallMs включает загрузку ответа и JSON.parse, но не проверочные утверждения. Стадии — диагностические обёртки с overhead; inclusive totalMs не суммировать, независимые медианы selfMs не обязаны складываться. readBytes не включает stat, не является физическим чтением диска при прогретом кеше ОС. Браузер/FPS/LAN/Wi-Fi/Windows/физические устройства не измерялись.

Это наблюдение конкретных прогонов с нефиксированным GC, не верхняя граница памяти или обещание универсального снижения RSS. Кеш удерживает один разобранный документ; 8 MiB входа не равны 8 MiB выделенной памяти.

## Проверки

Полный npm test — **104/104**, без пропусков. До правки три из пяти новых сценариев воспроизвели отсутствие переиспользования и гонку чтения. После изменения новый test/character-projection-cache.test.cjs проверяет:

- одно чтение неизменённого документа, неизменяемость вложенных снимков, независимые Set/visible, обновление ростера/геометрии, вытеснение кампании и новую фабрику после рестарта;
- внешнюю атомарную замену такого же размера и in-place изменение с фиксированным mtime: inode/ctime остаются значимыми;
- удаление, повреждённый JSON, ошибки stat/read, oversize и возврат к небольшому/legacy файлу без устаревших данных;
- замену во время чтения и ошибки первой/второй проверки метаданных: не допускаются старые документы в кеш;
- движение, дверь, раскрытие секрета, явное инвалидирование даже при совпадающих метаданных, отказ rename и независимость ранее возвращённого состояния.

Тест настоящего публичного HTTP-стенда обновлён: после прогрева positions-файл не читается, прозрачность стадий и все проверки полного ответа сохраняются. Полный интеграционный sync проверяет реальные роли, кампании, двери, переходы, секреты, туман, повторную публикацию и перезапуск. Синтаксис character-positions.js и двух тестов проверен. Новая браузерная приёмка не проводилась: интерфейс/отрисовка не менялись.

## Продолжение

B5b3g завершена, B5b3 целиком открыта. Кеш используется только mapState. projectionRevision по умолчанию и getPosition по-прежнему используют прежнее полное readState; изменяющие операции должны и дальше читать свежий независимый объект. Холодное чтение опубликованного манифеста, линейная проекция и дисковый пространственный индекс также остаются открытыми.

Следующая небольшая **B5b3h — проверка версии общего экрана без полного чтения состояния исследования**. /api/worlds/table/status вызывается при восстановлении синхронизации и использует projectionRevision. Подключить к этому чистому вычислению тот же проверяемый read-only документ, сохранив пересчёт версии по текущему fog и прежний путь мутаций. Дополнить стенд status-запросом и регрессиями: неизменённый документ не читается повторно, двери/движение/секреты/публикация/смена кампании немедленно отражаются, пропущенное событие и устаревший ответ не ломают синхронизацию. Измерить отдельно, не кешировать готовую версию/HTTP-ответ и не менять формат хранения/лимиты.
