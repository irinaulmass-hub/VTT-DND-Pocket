# B5b2a — применение из редактора и проверка транспорта

13 ноября 2026. База — `608eb603d5745ecbd26aec8b9a557ef46455b5a2` плюс изменения B5b2a. applicationRef оставлен null; одинаковые SHA-256 измеряемых файлов находятся в обоих JSON.

[PUT](B5B2A_PUT.json) · [POST](B5B2A_POST.json).

На том же стенде I1a использован предельный профиль: 125 районов, 3 000 объектов, 150 000 тайлов. Сначала полный PUT, затем district-apply; по пять последовательных запросов после одного прогрева. Автотесты и действия в браузере не выполнялись во время замеров. Сервер браузерной кампании ожидал без действий. ОС/CPU одинаковы в обоих отчётах: AMD EPYC 9V74 80-Core Processor, v24.22.1. Кеш прогрет, p95 ближайшего ранга при пяти выборках равен максимуму.

| Метрика применения | PUT | POST district-apply |
| --- | ---: | ---: |
| Запрос, байт | 6021159 | 282 |
| Ответ, байт | 6020878 | 38409 |
| HTTP, медиана мс | 327.34 | 399.50 |
| HTTP, p95 мс | 373.74 | 412.87 |
| Сервер, медиана мс | 284.78 | 396.40 |
| JSON.stringify запроса, медиана мс | 36.54 | 0.01 |

POST передаёт 282 байта вместо 6 021 159, ответ — 38 409 вместо 6 020 878. Однако HTTP по loopback медленнее: 399.5 против 327.3 мс. POST заново формирует подписи before/after полных снимков. Это измеренный результат всего обработчика, а не CPU-профиль отдельной функции; для точной доли HMAC нужен отдельный профиль.

Пик RSS сервера за профиль: PUT 325.2 MiB, POST 328.3 MiB; улучшение памяти не заявляется. Восстановление дельты Node-клиентом — дополнительно около 0.96 мс. Проверка снимков и восстановление после ошибок в браузерном редакторе в эти HTTP-времена не входят. Проверка успеха пропускает одинаковые ссылки неизменённых чанков/рецептов, не сериализуя каждый раз весь мир.

Оба прогона проверили сохранение/повторную загрузку, число объектов/рецептов и неизменность связанного дома/пары. FPS, Wi-Fi/LAN, реальные телефоны/ТВ и Windows не измерены. Полные чтения, HMAC и запись манифеста остаются задачей дальнейшей оптимизации. Лимиты мира не менялись.

```bash
npm run benchmark:world -- --profile limit --samples 5 --save-mode full --output /tmp/vtt-put-new.json
npm run benchmark:world -- --profile limit --samples 5 --save-mode district-apply --output /tmp/vtt-post-new.json
```

Запускать последовательно и выбирать новые пути. По умолчанию save-mode=full для совместимости прежних прогонов. preview-format=delta-v1. Исходники хешируются; отчёты не перезаписываются.
