В новом пути отличаются только три указанных рабочих модуля; SHA-256 всех измеряемых файлов сохранены. applicationRef=null, поскольку измерялся состав базы и новых диагностических файлов.

Сначала контроль, затем новый путь; по пять выборок после одного прогрева, limit-профиль (125 районов, 3 000 объектов, 150 000 тайлов / 599 чанков), save-mode district-apply, history-mode delta-v1, stages on. Тесты и браузерные действия во время замеров не выполнялись. Данные стенда временные; пользовательские кампании не использовались.

Среда: v24.22.1, linux x64, AMD EPYC 9V74 80-Core Processor. Кеш прогрет, GC сервера не принудительный. При пяти выборках p95 ближайшего ранга равен максимуму.

## Исправление сравнения стенда

Первый эксперимент выявил зависимость прежнего отпечатка от порядка ключей JSON. Переиспользованный индекс может перечислять чанки в ином порядке при полностью одинаковом мире. snapshotFingerprint теперь канонизирует ключи объектов перед SHA-256; порядок массивов остаётся значимым. Отдельный регрессионный тест проверяет это различие. Финальные контроль и новый путь повторно измерены одинаковым исправленным стендом. Отпечатки из старых отчётов до B5b3b напрямую с новым форматом сравнения не сопоставлять. Подписи истории приложения не менялись.

## Контракт и гарантии

- Внутренний store.writeDraftChanges(next, baseRevision, chunkChanges, tileLimit) получает уже проверенный сервером целевой снимок. chunkChanges составляется только из ключей серверной клеточной дельты после guard/HMAC и содержит полные замены чанков либо null для удаления. В HTTP новое поле не передаётся.
- Для storageVersion 1 повторно читается текущий манифест/ревизия; проверяется число тайлов через count индекса и замен. До любых записей отклоняются stale/missing/limit. Переиспользуется индекс чужих чанков, хешируются только замены. Новые файлы пишутся перед атомарным rename манифеста.
- Удалённый чанк исключается из индекса. Явный пустой объект чанка сохраняет прежнюю семантику полного пути; обычный генератор удаляет опустевший чанк через null. Метаданные карты/объектов/рецептов остаются целыми в манифесте.
- Ошибка записи чанка/временного манифеста/его переименования оставляет прежний индекс активным. Неиспользуемые новые файлы или .tmp могут остаться; существующие данные не удаляются. Повтор заменяет временные файлы и фиксирует ревизию один раз. Это прежняя модель одного синхронного Node-процесса, не новая многопроцессная транзакция и не гарантия пережить потерю питания.
- Legacy JSON использует прежний полный writeDraft после проверки ревизии, без миграции. PUT, публикация, переходы, роли/кампании, HMAC полного снимка и клиентская GET-сверка потерянного ответа сохраняют контракт.
