Полные карты, объекты, рецепты и ревизия обоих прогонов дали одинаковый verificationSha256. Пара переходов и связанный дом проверены внутри каждого прогона.

## Измеренные стадии

Медианы selfMs в профилированном прогоне. totalMs включают вложенные стадии, selfMs исключают их. Не складывать totalMs; медианы отдельных стадий также не обязаны складываться в медиану запроса.

| Стадия, мс | Предпросмотр | Применение | Undo | Redo |
| --- | ---: | ---: | ---: | ---: |
| store.readDraft | 45.82 | 39.12 | 42.42 | 43.58 |
| generation | 104.87 | 67.42 | 0.00 | 0.00 |
| signature.input | 196.50 | 189.68 | 107.10 | 103.54 |
| signature.crypto | 7.99 | 8.08 | 4.34 | 4.05 |
| movement.districtContext | 0.29 | 0.27 | 0.78 | 0.57 |
| store.writeDraft | 0.00 | 32.52 | 37.29 | 33.40 |
| Вне охваченных методов | 1.66 | 37.43 | 44.01 | 35.78 |

- store.readDraft включает чтение/JSON.parse манифеста и чанков. store.writeDraft включает перебор/хеширование чанков, запись новых файлов и полный манифест. Это границы существующих методов, а не чистое время дискового устройства.
- generation охватывает generationChange. movement.districtContext отдельно измеряет проверку пар/входов.
- signature.input — интервал между созданием HMAC и первым update в функции proof: нормализация, канонизация и JSON.stringify входа вместе. Эти три части не разделяются; небольшая подготовка обёртки тоже попадает в интервал. signature.crypto — создание/обновление/завершение HMAC. Для preview/apply выполняются две подписи, для Undo/Redo одна.
- district.*.selfMs в JSON содержит оставшуюся работу метода (включая валидацию и кодирование/восстановление дельты). unmeasuredMs содержит оставшееся время обработчика/HTTP: разбор запроса, валидацию маршрута, сериализацию ответа и прочее. Это не доказательство стоимости одной конкретной функции.

Подготовка полного входа подписи — крупнейшая измеренная стадия. Сам HMAC существенно дешевле. Полное чтение и запись тоже заметны. Нельзя объявлять криптографический расчёт единственной причиной задержки или обещать устранение всей задержки ограниченной записью.

## Следующий небольшой контракт B5b3b

Выбран первый срез хранилища: ограниченная запись изменённых **чанков** для уже проверенного District. Он сохраняет существующий формат и подписи. Пока это только контракт, реализация относится к следующей задаче.

1. Внутренний метод store принимает ожидаемую ревизию, заменённые/удалённые ключи чанков и проверенные новые метаданные карты. Не создавать новый публичный API и не принимать произвольную дельту без прежней проверки District.
2. Для storageVersion 1 повторно проверить ревизию манифеста, повторно использовать индекс неизменённых чанков, хешировать/писать только затронутые чанки; затем записать новый манифест атомарным rename. Число тайлов сверять по count индекса и замен. Пустой удалённый чанк исключать из индекса.
3. Старый JSON обслуживать прежним writeDraft без миграции. Старый PUT сохраняет контракт. Входы/возвраты, публикация, HMAC и проверка целевого снимка не меняются.
4. Проверить равенство с полным сохранением и повторное открытие, отрицательные координаты, удаление/пустой чанк, неизменность чужих файлов, старую ревизию и ошибку записи до переключения манифеста. Переиспользовать текущие тесты ролей/истории/потерянного ответа; повторить измерения на том же стенде.

Манифест с полными метаданными, readDraft и подпись полного снимка на этом срезе остаются. B5b3 в целом ещё открыта; следующий срез не является пространственным чтением или полноценной транзакцией нескольких процессов. Перед изменением схемы/ключа подписи нужен отдельный контракт и проверка совместимости. Лимиты не повышать.
