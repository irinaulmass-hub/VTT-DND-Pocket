# B5b3i — read-only метаданные публикации

14 ноября 2026. База — `c421e9de9126c10ff557e4f639d05aaad04c34e0`. Добавлен отдельный readPublishedView в world-store.js для проекции и activeNotice общего экрана. Прежние readPublished/readActiveWorld остаются свежими изменяемыми чтениями. Формат сохранений/HTTP, HMAC, роли, графика, лимиты и зависимости не менялись.

## Контракт

Один опубликованный манифест на фабрику store, ключ — абсолютный путь файла кампании плюс dev/ino/size/mtimeNs/ctimeNs (bigint stat). Смена карты/кампании/идентичности вытесняет прежний документ до чтения. После JSON.parse проверяется повторный stat. При замене/ошибке метаданных — прежнее некешируемое readManifest, при ошибке JSON/read или версии хранения прежний снимок не возвращается. Проверка storageVersion общая для двух путей.

Допуск — обычный файл до 8 MiB входного JSON по stat и фактическим UTF-8 байтам. Это не лимит мира и не оценка JS heap. Допущенное дерево глубоко заморожено итеративно. Legacy-публикации продолжают читаться полным независимым JSON без кеша; наличие chunk-draft проверяется каждый раз, поэтому staged manifest не меняет выбор прежнего формата. При возврате к chunk-формату старый legacy-снимок не переиспользуется.

readPublishedView создаёт новые внешние map/snapshot-объекты, но разделяет неизменяемые метаданные (объекты, кадр, жетоны и seen). Terrain **никогда не кешируется**: readChunks каждый раз загружает текущие переданные ключи, пустой список не читает местность. Прежний readPublished возвращает независимый изменяемый документ для команд мастера. writePublished/saveChunkPublished и updatePublishedState очищают кеш до записи, включая отказ commit. Опубликованная карта и её состояние по-прежнему переключаются прежним атомарным rename.

В worlds.js новый путь подключён только к activeNotice и GET /api/worlds/table. Готовая проекция/статус/HTTP-ответ/решение доступа не кешируются; фильтрация тумана/секретов и вычисление версии выполняются как раньше. Ручные правки публикации, capture исследования и прочие изменяющие операции продолжают использовать прежний свежий источник.

## Измерения

Контроль выполнен до изменения двух рабочих модулей: [туман on](B5B3I_CONTROL_FOG.json) и [off](B5B3I_CONTROL_CLEAR.json). SHA-256 этих модулей сверены с базой c421e9d. После 110 тестов тем же стендом выполнены [новый A](B5B3I_CACHED_FOG_A.json), [повтор B](B5B3I_CACHED_FOG_B.json), [без тумана](B5B3I_CACHED_CLEAR.json). Из измеряемых исходников отличаются только world-store.js и worlds.js; стенд/обёртки одинаковы. applicationRef=null, точные хеши записаны в sourceSha256.

125 районов, 3 000 объектов, 150 000 тайлов/599 чанков; насыщенная память 150 002 исторические записи клеток/2 997 объектов. Публичный loopback HTTP без cookie мастера, отдельные серверные процессы, временные кампании. Шесть последовательных запросов, один исключённый прогрев каждого, пять выборок — по 30 строк на прогон, всего 150 измеренных ответов. Все соответствующие responseSha256 совпадают, измеренных записей нет. Пользовательские данные не использовались.

Linux x64, Node.js 24.22.1, AMD EPYC 9V74; кеш ОС прогрет, GC не принудительный. HTTP wallMs включает загрузку и JSON.parse; утверждения выполняются после таймера. readBytes — readFileSync, не stat/existsSync и не физические байты диска при прогретом кеше ОС. Обёртки добавляют overhead; inclusive totalMs не суммировать, независимые медианы не обязаны складываться. Холодное чтение/замораживание, браузер/FPS/LAN/Wi-Fi/Windows/физические устройства не измерены.

HTTP-медианы с туманом, мс; A/B — два последовательных повтора:

| --- | ---: | ---: | ---: |
| status | 3.46 | 1.09 / 0.85 | 392,592 → 60 |
| near | 5.80 | 3.82 / 3.56 | 394,863 → 2,331 |
| adjacent | 6.13 | 4.20 / 3.77 | 396,924 → 4,392 |

Status: **3.46 → 1.09 / 0.85 мс**, readFileSync **392 592 → 60 байт**, ответ прежний — **213 байт**. Остаётся только JSON активного мира; проверки метаданных файла продолжаются при каждом запросе. При выключенном тумане status **3.32 → 1.13 мс**, чтение **392 593 → 60 байт**. Во всех новых тёплых строках отсутствует категория publishedManifest, terrain читается только для запрошенных существующих чанков.

Empty с туманом: **5.16 → 3.45 / 3.34 мс**, чтение **392 647 → 115 байт**, ответ 232 байта. Кроме active-world здесь читается ростер героя (55 байт), поскольку видимость вычисляется заново. Дальняя четырёхчанковая область: **8.15 → 6.16 / 6.06 мс**; её terrain-байты остаются. Линейный обход живых объектов/памяти в project ещё не заменён индексом.

Пик RSS процесса с туманом: 107.45 MiB в контроле, 102.04/105.81 MiB в повторах. Это наблюдение с нефиксированным GC, не обещание снижения/верхней границы памяти. Теперь могут удерживаться по одному документу исследования и публикации; их 8 MiB допуска относятся к входным файлам, не к суммарному JS heap.

## Проверки

Полный npm test — **110/110**, без пропусков, Node.js 24.22.1; синтаксис пяти изменённых/новых JS проверен. Новый test/world-store-view.test.cjs содержит пять сценариев:

- равенство прежнему чтению, одно чтение манифеста, глубокая неизменяемость метаданных и независимый terrain, пустые/сменяющиеся ключи, прежний изменяемый API;
- обновление кадра/жетонов/seen/fog/ревизии и новая публикация, явная инвалидация даже при совпадении метаданных, отказ rename без подмены прежнего состояния;
- вытеснение карты/кампании, новая фабрика, внешняя same-size замена и in-place ctime при фиксированном mtime;
- удаление/повреждение/неподдерживаемая версия/stat/read/oversize, выбор legacy при staged manifest и возврат к chunk-формату;
- повторное чтение terrain даже при неизменном манифесте, отказ только для запрошенного отсутствующего чанка, замена во время чтения и ошибка повторной проверки метаданных.

На прежнем пути тест воспроизвёл два чтения неизменённого манифеста вместо одного. HTTP-стенд после прогрева проверяет отсутствие positions/manifest-чтений и 60 байт active-world для status. Прежние sync/VM проверки ролей, памяти/секретов, публикации, управления картой, кампаний/перезапуска, пропущенного события/старого ответа проходят. Новая браузерная приёмка не проводилась: отрисовка и интерфейс прежние.

## Следующий срез B5b3j

Производный пространственный индекс **в памяти** для отбора объектов общего экрана по визуальным границам. Теперь опубликованные объекты и память имеют стабильные неизменяемые ссылки, позволяющие ограничить повторное построение индекса. Индекс должен зависеть от конкретного снимка, иметь ограниченный допуск/время жизни и сохранять прежний полный fallback для неподходящих/legacy данных. Формат на диске и лимиты не менять.

Критерии: побайтово/структурно одинаковая публичная проекция с эталонным полным обходом; кандидаты отбираются по запрошенным чанкам, поворотам и отрицательным визуальным выступам без дублей. Авторизация остаётся по глобальной опоре, видимая новая позиция подавляет старую память даже вне запроса, приоритеты масок/состояние двери/секреты сохраняются. Проверить число просмотренных кандидатов и измерить на этом стенде, не менять коллизии/LOS. Холодное полное чтение и дисковый пространственный индекс остаются открытыми; B5b3 целиком ещё не завершена.
