# B5b3h — проверка версии без повторного чтения исследования

14 ноября 2026. База — `c0c18b3f2fa85807a6835ffc4acc5c32314aab3f`. Изменён только default-путь projectionRevision в рабочем модуле character-positions.js: readProjectionState вместо полного readState. Формула версии, явно переданный state, HTTP/WS, роли, мутации, HMAC и форматы файлов прежние.

## Поведение

Чистое вычисление версии /api/worlds/table/status и mapState используют один проверяемый неизменяемый документ B5b3g. Версия вычисляется заново по ID карты и текущему fog: objects плюс sight только при включённом тумане. Итоговая версия и ответ status не кешируются. generation/publication/frame/party/blackout по-прежнему формируются из текущих источников. Вызов с явным state не читает файл.

Сохраняется контракт B5b3g: одна запись по абсолютному пути кампании и dev/ino/size/mtimeNs/ctimeNs; проверка до/после чтения, допуск 8 MiB входного JSON, глубокая неизменяемость и инвалидация до собственных записей. Мутации используют независимый readState; смена файла/кампании и ошибки не возвращают прежнее состояние. Это не кеш ролей или готовых ответов. Холодное чтение после изменения по-прежнему полное и включает замораживание. getPosition остаётся на прежнем пути.

## Стенд и контроль

scripts/world-table-benchmark.cjs расширен шестым запросом status, который идёт первым в каждом цикле. Проверяется весь публичный ответ, включая WORLD_UPDATE, текущую версию/кадр, party и blackout; карты, памяти и объектов в нём нет. Прежние пять регионов/секреты/память проверяются как раньше. Guarded stages дополнен positions.projectionRevision. Стенд/обёртки не подключаются при обычном запуске приложения.

Финальные пять прогонов:

- [Контроль с туманом](B5B3H_CONTROL_FOG.json), [без тумана](B5B3H_CONTROL_CLEAR.json): отдельная временная копия проекта с новым стендом и точным character-positions.js из базы c0c18b3 (проверен Git blob SHA).
- [Новый путь A](B5B3H_CACHED_FOG_A.json), [повтор B](B5B3H_CACHED_FOG_B.json), [без тумана](B5B3H_CACHED_CLEAR.json): рабочая версия после тестов.

В измеряемых sourceSha256 между контролем и новым путём отличается только character-positions.js; стенд и обёртки совпадают. applicationRef=null, точные исходники зафиксированы хешами. Соответствующие responseSha256 совпадают для всех шести запросов; измеренных записей нет.

125 районов, 3 000 объектов, 150 000 тайлов, 599 чанков terrain; память 150 002 исторические записи клеток/2 997 объектов, файл состояния 4 022 228 байт. Один наблюдающий герой. Шесть последовательных публичных GET без cookie мастера, один исключённый прогрев каждого, затем пять выборок — по 30 строк на прогон, всего 150 измеренных ответов. Отдельные серверные процессы и одноразовый DATA_DIR, пользовательские кампании не использовались.

Linux x64, Node.js 24.22.1, AMD EPYC 9V74. Кеш ОС прогрет, принудительного GC нет; p95 при пяти выборках равен максимуму. HTTP wallMs включает загрузку и JSON.parse, утверждения выполняются после таймера. Диагностика добавляет overhead; stat не включён в readBytes. Inclusive totalMs не суммируются, медианы стадий независимы. Браузер/FPS/LAN/Wi-Fi/Windows/физические устройства не измерялись.

В остальных пяти запросах состояние уже переиспользовалось с B5b3g: их объёмы чтения не изменились. Колебания времени в таблице не объявляются ускорением этих запросов. Опубликованный манифест всё ещё читается полностью: 392 532 байта при включённом тумане; помимо него status читает 60 байт active-world.json. Ускорение относится к повторным запросам с неизменённым допущенным документом; первый запрос/уведомление после записи всё ещё может читать и замораживать полное состояние. Память/верхняя граница heap этим срезом не объявляются улучшенными.

## Проверки

Полный npm test — **105/105**, без пропусков, Node.js 24.22.1; синтаксис пяти изменённых JS проверен. Новый сценарий в test/character-projection-cache.test.cjs на старом коде показал четыре чтения вместо одного, после правки проходит. Проверяет совместное переиспользование mapState/версии; пересчёт для другого ID и fog; явный state без I/O; обновления после двери/движения/секрета; кампанию, внешнюю атомарную замену, повреждение и удаление файла.

Тест HTTP-стенда расширен status: полный ответ сравнивается с независимым ожидаемым notice, замеры стадии версии и отсутствие чтения terrain/positions проверяются после прогрева. Сохраняются прозрачность on/off обёрток, изоляция DATA_DIR и защита старого отчёта. Прежние проверки B5b3g покрывают инвалидацию, неизменяемость, oversize/legacy/ошибки и гонки чтения.

test/world-table-sync.test.cjs проходит: восстановление после ошибки чанков/пропущенного WS, игнорирование запоздалых HTTP ответов, защита затемнения от старого polling. Полный sync.test.cjs проверяет настоящий HTTP/WS, свежие версии публикации/шага/двери/секрета, кампании, туман on/off, затемнение, скрытие мира и перезапуск. Клиентская логика D3 и графика не менялись; новая браузерная приёмка не проводилась.

## Следующий срез B5b3i

Ограниченное read-only переиспользование опубликованного манифеста для общего экрана: это оставшиеся примерно 393 KB на каждый повторный status-запрос и значимая часть чтения viewport. Сохранить отдельный свежий путь для операций, изменяющих публикацию; нельзя замораживать и отдавать им общий документ. Повторно читать только запрошенные terrain-чанки, не кешировать готовую проекцию/ответ и не расширять авторизацию.

Критерии: ограниченное число/размер допуска документов, идентичность пути/файла/кампании и инвалидация публикации/кадра/жетонов/тумана; отсутствие повторного чтения неизменённого манифеста; свежие выбранные чанки; точное равенство публичных ответов и сценариев ошибок/legacy/перезапуска. Повторить этот стенд с контролем. Формат, HMAC, лимиты и пользовательские данные не менять. Дисковый пространственный индекс и линейный отбор объектов остаются отдельными открытыми задачами; B5b3 целиком не завершена.
