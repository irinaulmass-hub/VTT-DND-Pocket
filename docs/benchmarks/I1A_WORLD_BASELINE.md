# I1a — базовые измерения насыщенного мира

13 ноября 2026. Измеряемый код приложения: `9eadec84e817c5cea80ea973931dc8a49407b533`. Исходные выборки: [I1A_WORLD_BASELINE.json](I1A_WORLD_BASELINE.json).

## Метод

Изолированный локальный сервер Node.js v24.22.1, Linux 6.18.57, x64, AMD EPYC 9V74 80-Core Processor. ОС сообщает 9 доступных логических процессоров и 9.73 GiB RAM; это сведения среды, а не гарантия ресурсов пользовательского компьютера.

Для каждого профиля создаётся отдельная временная кампания и новый процесс сервера. Фикстура строится вне измеряемого сервера: районы 64×64 с шагом 72 клетки, один связанный с интерьером дом, дополнительная область покрытий вдали от первого района. Большой профиль использует текущие пределы модели; лимиты не увеличивались.

После одного неучитываемого прогрева выполнено 5 последовательных выборок каждой операции. Ни тесты, ни другие профили параллельно финальному прогону не запускались. Файловый кеш ОС прогрет; холодный диск и сброс кешей не измерялись. Серверный GC не форсируется. HTTP идёт по loopback: время включает передачу тела ответа и JSON-разбор клиентом. JSON.stringify запроса измеряется отдельно и не входит в wallMs.

p95 рассчитан методом ближайшего ранга: при пяти выборках это максимум. Это небольшая воспроизводимая базовая выборка с min/median/p95/max, а не оценка стабильного хвоста задержек.

Probe подключается только к тестовому серверу через --require и требует временную кампанию/IPC. Он считает вызовы fs.readFileSync/writeFileSync и логические UTF-8 байты под DATA_DIR; это не измерение физического диска или fsync. Время serverMs — от HTTP request до finish; память — heap после запроса, RSS и максимум RSS процесса за его жизнь. Построение фикстуры в этот максимум не входит.

## Вывод и следующая задача

На предельном профиле сохранение, повторная загрузка и регенерация прошли. Число домов и состояние рецептов проверены, файл входа/возврата остался неизменным. Это подтверждает корректность измеренного сценария в текущих лимитах, но не готовность огромного мира к выпуску.

Первое измеренное узкое место — полный защищённый предпросмотр: медиана 449.5 мс при изменении одного района и ответ около 10.04 MB. Медиана обработчика сервера — 362.7 мс. Полная загрузка читает весь манифест и 599 чанков; последующее сохранение всё ещё переписывает крупный манифест F4, даже когда медиана числа файловых записей равна 1 благодаря повторному использованию хешированных чанков.

Чтение четырёх опубликованных чанков существенно дешевле. Хранилище всё равно читает метаданные всех объектов из манифеста; публичная проекция отфильтровывает объекты по запрошенной области, поэтому игроки не получают весь список.

Следующая небольшая задача B5a — сократить полные F4-снимки в ответе предпросмотра района, передавая изменение выбранного участка и сохраняя проверку связей, подписанную историю и совместимость. Затем повторить этот же стенд и сравнить байты, wallMs/serverMs и память. Изменение файлового формата, увеличение лимитов или замена базы не являются результатом I1a.

Не измерены Canvas/FPS, интерактивная задержка браузера, одновременные запросы, Wi-Fi/LAN, физические телефоны/ТВ и Windows. Целевые 60 FPS/300 мс для выпуска этими числами не подтверждаются.

## Повтор

```bash
npm run benchmark:world -- --samples 5 --ref 9eadec84e817c5cea80ea973931dc8a49407b533 --output /tmp/vtt-world-baseline-new.json
```

Для короткой проверки добавьте `--profile small`; также доступны `medium`, `limit`, `all` (по умолчанию). `--samples` допускает 1–10. Выберите новый путь отчёта: существующий файл никогда не перезаписывается. Входящий DATA_DIR игнорируется; сервер всегда получает собственный mkdtemp. Временная кампания удаляется после остановки сервера.

Два теста проверяют реальный HTTP-прогон, численные измерения, сохранность внешнего DATA_DIR, запрет перезаписи отчёта и неверные аргументы. Полный `npm test`: **67/67**.
