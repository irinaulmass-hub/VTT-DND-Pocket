# B5b2b — транспорт Undo/Redo District

13 ноября 2026. База `64ff80092c100f557b5190ceefbde9b1f79f9375` плюс изменения B5b2b. applicationRef=null; совпадающие SHA-256 исходников в обоих JSON проверены перед фиксацией.

[Полный PUT](B5B2B_PUT.json) · [Компактный POST](B5B2B_DELTA.json).

Два последовательных прогона того же limit-профиля: 125 районов, 3 000 объектов, 150 000 тайлов/599 чанков. Node.js 24.22.1, Linux x64, AMD EPYC 9V74. Применение в обоих случаях district-apply, предпросмотр delta-v1; различается только history-mode. Сначала full, затем delta-v1, по пять выборок после одного прогрева. Во время замеров тесты и действия в браузере не выполнялись. Каждый Undo/Redo отдельно проверен последующим GET вне измеряемого времени. Оба статуса verified.

Пик RSS за весь профиль: PUT 344.2 MiB, delta-v1 342.7 MiB. Это пик всего процесса, не отдельной операции, улучшение памяти не заявляется.

Компактный запрос содержит один рецепт и изменённые клетки/элементы; подтверждение — 77 байт на этой фикстуре. В данном loopback-прогоне история быстрее. HTTP wall включает передачу и JSON.parse; сериализация запроса измеряется отдельно. Восстановление и сверка снимка браузером не входят в замер. Канонизация/HMAC полного снимка, полное readDraft и запись манифеста сохраняются; ограниченная запись хранилища ещё не реализована.

Кеш файловой системы прогрет; сборка мусора принудительно не вызывается. p95 ближайшего ранга при пяти выборках равен максимуму; выборка мала. Не сравнивать абсолютные времена с другими средами/старыми отчётами. FPS, Wi-Fi/LAN, физические телефоны/ТВ и Windows не измерены. Метаданные protectedTiles могут увеличить запрос: 38 KB не гарантированный максимум, сервер сохраняет прежний лимит JSON 8 MiB. Лимиты мира не повышены.

Команды воспроизведения (по очереди; выходные пути должны быть новыми):

```bash
npm run benchmark:world -- --profile limit --samples 5 --save-mode district-apply --history-mode full --output /tmp/b5b2b-full-new.json
npm run benchmark:world -- --profile limit --samples 5 --save-mode district-apply --history-mode delta-v1 --output /tmp/b5b2b-delta-new.json
```

history-mode по умолчанию none, сохраняя прежние прогоны. B5b3a должна измерить стадии чтения/расчёта/подписи/записи перед выбором ограниченной операции.
