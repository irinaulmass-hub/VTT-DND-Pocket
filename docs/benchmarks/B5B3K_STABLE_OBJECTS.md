# B5b3k — стабильные опубликованные объекты после обновления состояния

Дата: 14 ноября 2026. База: `2d916e57cdfca80c525016893bf740458c3c4cf6` (B5b3j). Это проверка серверного чтения; графика и FPS не менялись.

## Контракт

readPublishedView удерживает один кандидат массива объектов по абсолютному пути файла. После успешного нового чтения манифеста, проверки версии и stat до/после сравнивает весь массив через node:util.isDeepStrictEqual. При полном равенстве значений/типов/порядка массива новый неизменяемый манифест использует прежний неизменяемый массив. Порядок ключей записи не значим для сравнения; порядок объектов значим. Кадр, жетоны, seen, fog, ревизия и прочие метаданные всегда берутся из свежего документа.

Кандидат не служит источником данных при ошибке. Смена пути, stat/read/parse/проверки, гонка, oversize и legacy не допускают переиспользования старого массива. Допуск — прежние 8 MiB входного документа плюс не более objectLimit (3 000) объектов; сверх этого чтение продолжает прежний путь. Слишком глубокое сравнение безопасно пропускает переиспользование. Строковые отпечатки не сохраняются; -0 отличается от 0, Infinity — от null. readPublished и команды по-прежнему получают независимые изменяемые снимки.

## Метод

Отдельная копия контрольного сервера содержит точный world-store.js базы (Git blob `2f57ab47c5bf2af79c800c70916403a31a1e3a16`). Диагностика в обеих копиях одинаковая; среди sourceSha256 отличается только world-store.js. applicationRef указывает базу, точные изменённые исходники определяются sourceSha256, а не объявляются уже закоммиченными.

Пять последовательных прогонов: два контроля (fog on/off), два новых повтора с туманом и один без. Каждый запускает сервер с одноразовой кампанией: 3 000 объектов, 150 000 тайлов, 2 997 запомненных объектов. После шести первых GET каждый из пяти циклов делает настоящий мастерский frame POST, затем шесть публичных GET без мастерской cookie. Учётные данные временные и в отчёт не попадают.

Всего 150 измеренных GET, 30 первых GET и 25 POST. POST и чтения измеряются раздельно. updateCycles хранит суммы по каждому циклу: firstReadsMs = status + near, updateAndFirstReadsMs = POST + status + near; ниже приведены медианы этих сумм, а не суммы независимых медиан. Первый цикл сохранён в warmupRows, исключён из summary. OS-кеш тёплый, принудительного GC нет.

```sh
node scripts/world-table-benchmark.cjs --profile limit --samples 5 --fog on --state-updates on --ref 2d916e57cdfca80c525016893bf740458c3c4cf6 --output /tmp/table-state-updates.json
```

Выходной файл должен отсутствовать. Без --state-updates поведение стенда прежнее. Индексные array/dictionary-счётчики обозначают форму источника; в этой сцене это соответственно публикация и память.

## Ограничения и следующий шаг

Изменения жетонов/seen/fog покрыты store-тестами; контролируемый HTTP-замер делает только frame POST. Движение персонажа и обновление памяти этим сравнением не измерялись. Первое построение сохраняется: первые near с туманом 67.89 мс в контроле и 49.85 / 33.59 мс в новых прогонах (по одной строке, JIT/GC смешаны); без тумана 15.82 → 29.44 мс. Нельзя считать это доказанным улучшением холодного запуска.

Остаются полное холодное чтение, первое построение и перестроения памяти после исследования, полный манифест при state write и дисковый пространственный индекс. Следующая B5b3l — управляемый профиль изменения исследования: отдельно измерить подтверждённое движение/обновление памяти и первые чтения, проверить актуальность тумана/секретов/версий и выбрать ограниченный контракт следующей оптимизации. Не вводить кеш решений доступа и не повышать лимиты. B5b3 целиком открыта; FPS, браузер, LAN, Windows и физические устройства не проверялись заново.
